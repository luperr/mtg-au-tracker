Verdict: Scrymarket is production-grade across the board. Container hardening (non-root, read-only, no-new-privileges, network segmentation), full VLAN network isolation on Proxmox (3 VLANs, SSH hardened, 2FA), and a complete observability stack (Promtail → Loki, cAdvisor → Prometheus → Grafana) are all live. The remaining gaps are focused: pino not wired (Loki receiving unstructured logs), price_history needs partitioning (2.7M rows), the DFC unmatched card bug, and zero test coverage on critical matching logic.

Security Audit

Security Review

Overall posture: Strong. The production docker-compose is significantly hardened — non-root UIDs, read-only filesystems, no-new-privileges, frontend/backend network isolation, DB never exposed externally. Promtail and cAdvisor are co-deployed for log shipping and container metrics. Prometheus/Loki/Grafana live on a separate monitoring LXC on vmbr2. The remaining gaps are around package pinning, pino not yet wired (so Promtail is shipping sparse logs), and the Proxmox host itself still needing hardening.
✓
Non-root container UIDs
Scraper runs as 1002:1002, web as 1001:1001. Neither container can escalate to root. This is the correct approach and was previously listed as a gap — it's done.
✓
Read-only container filesystems
read_only: true on scraper, web, tunnel, and promtail. Only explicitly declared tmpfs and named volumes are writable. Significantly limits blast radius of any container compromise.
✓
no-new-privileges on all containers
security_opt: no-new-privileges:true prevents privilege escalation via setuid binaries inside any container. Applied consistently across scraper, web, tunnel, and promtail.
✓
Network segmentation — frontend / backend split
DB is backend-only and never reachable from the tunnel or internet. Web sits on both networks. Tunnel is frontend-only and can only reach the web container. Correct isolation.
✓
DB not exposed externally
PostgreSQL has no ports: binding — only reachable on the internal Docker backend network. Combined with network segmentation, the DB surface is minimal.
✓
Cloudflare Tunnel — zero open inbound ports
All public traffic routes via Cloudflare edge. No firewall rules, free TLS, DDoS protection. cAdvisor metrics port bound to 10.10.20.10:8080 — Services VLAN only, not internet-facing.
✓
Full observability stack live
Promtail + cAdvisor co-deployed in app compose. Prometheus and Grafana running in a separate monitoring repo on the vmbr2 monitoring VLAN LXC. Scrapes cAdvisor at 10.10.20.10:8080 via inter-VLAN routing. Complete metrics and log pipeline is operational.
✓
Next.js security headers
CSP, X-Frame-Options, and related headers configured via Next.js config. Mitigates XSS and clickjacking at the HTTP layer.
⚠
Unpinned image tags — :latest on three containers
grafana/promtail:latest, cloudflare/cloudflared:latest, and gcr.io/cadvisor/cadvisor:latest all use floating tags. A breaking upstream change will silently affect your next docker compose pull. postgres:16-alpine is correctly pinned to a major version.
→ Pin to specific digest or semver tag: e.g. grafana/promtail:3.4.2, cloudflare/cloudflared:2025.4.0. Add docker compose pull to a monthly review checklist rather than relying on auto-updates.
⚠
cAdvisor runs privileged
privileged: true on cAdvisor is standard for container metrics collection (needs access to cgroups and the host filesystem). It's a known trade-off, not a mistake — but worth documenting in CLAUDE.md so it's not accidentally removed or questioned.
→ Add a comment in docker-compose explaining why privileged is required. Consider binding to vmbr2 address only once monitoring VLAN is set up (currently on 10.10.20.10 which is Services VLAN — check this matches your planned topology).
⚠
pino not wired — Promtail shipping sparse logs
Promtail is running and shipping logs to Loki, but the scraper and web are still using console.log. That means Loki is receiving unstructured text rather than structured JSON — no queryable fields, no log levels, no context. Promtail without pino is like having a dashboard with no data.
→ Wire pino to scraper first — it's the most log-dense service. One afternoon of work makes Loki dramatically more useful.
✓
Proxmox network fully hardened
3-VLAN segmentation complete: management (vmbr0), services (vmbr1), monitoring (vmbr2). Docker LXC is on the services VLAN. SSH hardened, 2FA enabled on Proxmox host. This is a strong infra posture.
⚠
No rate limiting on web API routes
Search and card detail API routes have no rate limiting. A scraper targeting your own site could exhaust the DB connection pool. Low risk now, real risk with public traffic growth.
→ Add @upstash/ratelimit or a Cloudflare rate limit rule (free tier). 100 req/min per IP is a reasonable default for the search endpoint.
⚠
Static AUD/USD rate
AUD_USD_RATE=0.65 env var — the AUD has moved meaningfully vs USD over the past year. USD reference prices shown to users will silently drift from reality.
→ Fetch from RBA or Open Exchange Rates API daily, cache in DB or Redis.
ℹ
No dependency audit in CI
No GitHub Actions workflow — pnpm audit isn't automated. Known vulnerabilities won't surface until manually checked.
→ Simple workflow: on push → pnpm install + pnpm audit + pnpm typecheck.
ℹ
No authentication layer
Currently a read-only public app — no auth needed now. B2B store dashboards (Phase 3) will require it. Plan the auth layer before building the dashboards, not after.
→ NextAuth.js with GitHub/Google OAuth. Keep out of scope until Phase 3 is started.

Deliberately out of scope for now: Deck builder integration, international price comparison, MTG Arena / MTGO price tracking, social features (comments/ratings), mobile app, ML-based price prediction.
